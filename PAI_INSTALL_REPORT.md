## TL;DR

```bash
# 1. Fork on GitHub, then clone YOUR fork (the cascade assumes a personal fork)
git clone https://github.com/<your-username>/pai-obsidian.git
cd pai-obsidian

# 2. Run the bootstrap installer (installs Bun/Git if missing, then a 9-step wizard)
bash Releases/v5.0.0/.claude/install.sh

# 3. Obsidian layer (this fork's reason for existing) — point it at your vault + tools
bun install -g qmd defuddle
export VAULT_DIR="$HOME/path/to/your/obsidian/vault"   # add to your shell profile
qmd update                                              # build the search index once
```

The installer copies `.claude/` → `~/.claude/` and wires the skills into Claude Code. After
it finishes it launches `pai`; run `/interview` to personalize.

> ⚠️ **This is alpha software** (the installer banner says so). Expect rough edges, and read
> the "Known watch-outs" section before relying on it day-to-day.

## 1. What you're installing

`pai-obsidian` is the middle tier of a three-tier cascade: **`danielmiessler/PAI` (upstream)
→ `pai-obsidian` (this public fork) → your private fork**. It ships:

- **46 skills** wired into Claude Code (39 general + **7 vault-native Obsidian skills**:
  Qmd, ObsidianMarkdown, ObsidianBases, ObsidianCLI, SecondBrain, ProjectManagement,
  DailyRituals). More optional skills live under `Packs/` for manual install.
- A **PAI runtime** (Algorithm, Memory, Pulse dashboard, hooks) under `~/.claude/PAI/`.
- An **Obsidian vault scaffold** (`inbox/ ready/ plan/ thinking/ domains/ bases/ dashboards/`).

The whole thing runs on **Bun + TypeScript** (never npm/Python). Platform: **macOS or
Linux only** — `install.sh` exits on anything else.

## 2. Prerequisites

| Tool | Required? | Installer auto-handles? | Notes |
|---|---|---|---|
| `bash` + `curl` | Yes | — | Must already be present; installer aborts without curl |
| **Git** | Yes | ✅ (brew / apt / yum / Xcode CLT) | |
| **Bun** | Yes | ✅ (`curl https://bun.sh/install`) | Also wires `~/.bun/bin` into `.zshenv`/`.zprofile`/`.zshrc`/`.bash_profile` + a system symlink so Claude Code **hooks** can spawn `bun` in non-interactive shells |
| **Claude Code** | Yes | ⚠️ "will install during setup" | The CLI you actually drive PAI through ([claude.ai/code](https://claude.ai/code)) |

| **defuddle** | Only for `/ingest-url` | ❌ manual | `bun install -g defuddle` — external CLI |

Skill tool dependencies are **not** vendored (no `node_modules` committed), but the tools are
zero-dep Bun scripts; `bun` resolves what little they need at runtime. No repo-wide
`bun install` step is required.

## 3. Step-by-step: what `install.sh` does

`install.sh` is a **bootstrap** — it guarantees Bun/Git, then hands off to a TypeScript
wizard (`PAI/PAI-Install/main.ts`). The wizard auto-picks **GUI** (Electron) on a desktop, or
**CLI** when headless / over SSH / in CI. The CLI wizard runs **9 steps** (resumable):

| # | Step | What it does |
|---|---|---|
| 1 | System Detection | OS, installed tools, existing PAI install |
| 2 | Prerequisites | Ensures Git, Bun, Claude Code |
| 3 | API Keys | Finds/collects an **ElevenLabs** key (for voice) — optional |
| 4 | Identity | Your name, **DA name**, timezone, catchphrase |
| 5 | PAI Repository | Copies the bundle into `~/.claude` (uses local files via `PAI_BUNDLE_DIR`, not a re-clone) |
| 6 | Configuration | Generates `settings.json`, env files, and the directory structure |
| 7 | DA Voice | ElevenLabs key + voice pick + starts/test the voice server (optional) |
| 8 | Telegram Bot | Optional Pulse↔Telegram chat/notifications |
| 9 | Validation | Verifies completeness, prints a summary |

On success it execs `zsh -i -c 'source ~/.zshrc && pai'` — i.e. it drops you straight into
the `pai` launcher. If headless, it prints `source ~/.zshrc && pai` for you to run.

## 4. Secrets & API keys

Keys are **not** stored in config files — `PAI_CONFIG.yaml` only stores the key *names*; the
actual secrets live in environment variables / `~/.claude/.env` (generated by wizard step 6;
no `.env.example` ships). What each key unlocks:

| Env var | Needed for | Required? |
|---|---|---|
| `ANTHROPIC_API_KEY` | PAI's `Inference.ts` tool + some skills | Needed for tool-level inference. Claude Code itself can also auth via your Anthropic **subscription login** instead of a key |
| `ELEVENLABS_API_KEY` (+ `ELEVENLABS_VOICE_ID`) | DA **voice** / Pulse notifications | Optional |
| `OPENAI_API_KEY` | Art / some research skills | Optional, per-skill |
| `GEMINI_API_KEY` | Art (Nano Banana / Gemini) | Optional, per-skill |
| `FRED_API_KEY` | USMetrics (economic data) | Optional, per-skill |
| `APIFY_TOKEN` / `APIFY_API_KEY` | Apify scraping | Optional, per-skill |

**Minimum to be useful:** Claude Code auth (subscription or `ANTHROPIC_API_KEY`). Everything
else is opt-in per the skills you actually use.

## 5. Obsidian layer setup (the point of this fork)

The 7 Obsidian skills operate on a **split**: your notes live under `$VAULT_DIR`; PAI runtime
state lives under `$PAI_DIR`. You must set this up manually after the wizard:

```bash
# External CLIs (not bundled)
bun install -g qmd          # semantic vault search — used by /ask /search /context + all capture workflows
bun install -g defuddle     # clean-markdown URL extraction — used by /ingest-url

# Point at your vault (add BOTH exports to ~/.zshenv or ~/.zshrc so they persist)
export VAULT_DIR="$HOME/path/to/your/obsidian/vault"
# (OBSIDIAN_VAULT also works as a fallback name)

qmd update                  # build the search index once; re-run after bulk note changes
```

- If `qmd` isn't on `PATH`, **search and dedup steps fail** across SecondBrain.
- `ResolveRoot.ts` falls back to `git rev-parse --show-toplevel` for `$VAULT_DIR` (repo==vault
  setups) and to `~/.claude` for `$PAI_DIR` — but for a real Obsidian vault you should set
  `$VAULT_DIR` explicitly.
- `.obsidian/` in this repo ships **config JSONs only** (appearance, hotkeys, enabled-plugins
  list). On first open, Obsidian re-installs the listed community plugins.

## 6. Post-install

1. **`pai`** — the launcher the installer drops you into (a shell function added to your
   profile; re-run `source ~/.zshrc && pai` any time).
2. **`/interview`** — the DA walks you through TELOS, identity, projects, preferences
   (pause/resume anytime). This rewrites the bootstrap-default `PAI/USER/*` files with your
   real data; until you do, identity/voice/goals are placeholders.
3. Edit `~/.claude/PAI/USER/DA/README.md` to tune your DA's identity/voice/personality.

## 8. ⚠️ Known watch-outs (found during the scan)

1. **`PAI_DIR` semantics — RESOLVED (was a real bug).**
   Earlier, the SecondBrain/Obsidian layer assumed `PAI_DIR=${HOME}/.claude` while the
   framework's `settings.json` sets `PAI_DIR=${HOME}/.claude/PAI`, so a real install produced
   wrong paths (`~/.claude/PAI/skills/…` and a double-`PAI` `~/.claude/PAI/PAI/MEMORY/…`).
   This is now fixed: the workflows reference tools via `$HOME/.claude/skills/…` (skills are
   siblings of `PAI/`) and runtime state via `$PAI_DIR` (`~/.claude/PAI`), and `ResolveRoot.ts`
   defaults/honors `$PAI_DIR=~/.claude/PAI`. **No env override is needed** — just keep the
   `settings.json` default. (Do NOT set `PAI_DIR=~/.claude` — that would re-break it.)

2. **README skill-count drift.** `README.md` says "39 skills … Obsidian: *(coming in Phase 3)*"
   in its table, while the same file's intro and `CLAUDE.md` correctly say **46 skills incl. 7
   Obsidian**. The Obsidian skills *did* ship — the table row is stale. Install still works.

3. **Alpha.** The installer banner literally says "Alpha — rough edges expected."

4. **Hooks need `bun` on a non-interactive PATH.** The installer handles this (symlink +
   `.zshenv` export). If voice/statusline/hooks silently don't fire, verify
   `sudo ln -sf "$HOME/.bun/bin/bun" /usr/local/bin/bun`.

5. **Fork first.** The three-tier cascade and "sync with upstream" flow assume you cloned
   *your own fork*, not this repo directly.
